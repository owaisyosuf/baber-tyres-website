@AGENTS.md

## What this is

Marketing + catalog site for Baber Tyres Corporation (tyre importer/dealer, M.A. Jinnah Road, Karachi). It is **not a store**: every surface ends in a WhatsApp/call inquiry — no cart, no contact form, no email. Next.js 16 App Router + Tailwind v4 + Sanity (content, embedded Studio at `/studio`).

## Specs drive the work

`specs/` is authoritative: `constitution.md` (non-negotiables) → `requirements.md` → `design.md` → `tasks.md` (T001–T039, dependency-ordered, with owner-approval checkpoints ◆1 after T016 and ◆2 before launch). Work one task at a time, one commit per task named `T0NN: …`, and stop at checkpoints. Check `tasks.md` for a task's acceptance criteria and its "Definition of Done" (build passes, 360/768/1440px, keyboard/focus, only Constitution §IV tokens, Server Component unless interactivity needs `"use client"`).

Content rules that are easy to break: no invented claims, prices, awards, reviews, or staff/stock photography (Constitution §II.6); only three services exist (fitting, computerized alignment, computerized balancing — never puncture repair or nitrogen); delivery is always "charges apply", never free.

## Commands

```bash
npm run dev                       # next dev
npm run build                     # next build — slow (5–12 min), studio bundle dominates
npm run lint                      # eslint
npx tsc --noEmit                  # typecheck
npm test                           # vitest run — ~2 min, see note below
npx vitest run src/lib/whatsapp.test.ts      # single file
npx vitest run -t "name of test"             # single test by name
npm run typegen                   # regenerate src/sanity/types.ts from schemas + queries
npm run seed                      # dry run; `npm run seed -- --write` applies (needs SANITY_API_WRITE_TOKEN)
```

`src/sanity/schemas/index.test.ts` imports `sanity` and takes ~70s alone; it is not hung. Vitest only picks up `src/**/*.test.ts`.

Env lives in `.env.local` (names in `.env.example`). `NEXT_PUBLIC_*` are public; `SANITY_API_READ_TOKEN`, `SANITY_API_WRITE_TOKEN` (seed script only), and `SANITY_REVALIDATE_SECRET` are server-only.

## Architecture

**Two root layouts, no `app/layout.tsx`.** `src/app/(site)/` is the public site (fonts, Tailwind tokens in `globals.css`); `src/app/studio/` is a separate root layout for the embedded Sanity Studio so it never inherits site styles. `src/sanity/config.ts` holds the real Studio config (root `sanity.config.ts` only re-exports it for the CLI). `@/*` → `src/*`.

**Data flow: Sanity → cached GROQ → tag revalidation.** `next.config.ts` enables `cacheComponents`, so every fetch in `src/lib/sanity/queries.ts` is a `"use cache"` function with `cacheTag(...)` + `cacheLife("max")`. Publishing in Studio fires a webhook to `src/app/api/revalidate/route.ts`, which verifies the signature (`next-sanity/webhook`), maps `_type`/`slug` to tags via `src/lib/sanity/revalidate.ts`, and calls `revalidateTag(tag, { expire: 0 })`. **The tag names are a contract between `queries.ts` and `revalidate.ts`** (`product`, `brand`, `category`, `service`, `settings`, plus `product:<slug>` / `brand:<slug>` / `category:<slug>`) — add or rename a tag in both. The webhook projection in Sanity must be `{ _type, "slug": slug.current }`.

**Queries and generated types.** Each query is one self-contained ``defineQuery(`…`)`` literal (no interpolated fragments) so typegen can scan it; user input only ever reaches GROQ as `$params`. `src/sanity/types.ts` is generated by `scripts/generate-types.ts` (which calls `@sanity/schema`/`@sanity/codegen` directly because the `sanity` CLI typegen hangs on this machine) — never hand-edit it; it is eslint-ignored.

**Single sources of truth.** All contact/NAP/hours values come from `src/lib/site.ts` (mirrors the `siteSettings` singleton); no phone number, address, or hours string may be typed into a component or elsewhere. Tyre size display goes through `formatTyreSize` in `src/lib/format.ts` (honours `sizeLabelOverride` for commercial sizes like `11R22.5`), prices through the PKR formatter there, and every WhatsApp link through `src/lib/whatsapp.ts`.

**Sanity model** (`src/sanity/schemas/`): `brand` (required `relationship`: importer | dealer | stocked — drives badges sitewide), `category`, `product` (numeric width/profile/rim for filtering, plus optional `sizeLabelOverride`), `service`, `siteSettings` (singleton, enforced in `src/sanity/structure.ts` by a fixed `documentId("siteSettings")`, not by the schema).

**Seed data** (`src/sanity/seed/data.ts`, run by `scripts/seed.ts`): confirmed facts are published documents; sample products with placeholder prices are `drafts.` documents titled `[SAMPLE] …` so the live site (published perspective) never shows them. The seed uses `createIfNotExists` and won't overwrite owner edits. Only 7 of the "20+" brands are seeded — the rest are pending owner input (OQ-2); don't invent brand names.

**UI layer.** Primitives in `src/components/ui/`, SVG icons/tread motif/radial glow in `src/components/icons/` (no icon font or runtime icon library). Design tokens (Constitution §IV) are CSS variables in `globals.css` wired into the Tailwind theme — use them, no ad-hoc colors/spacing/radii. Amber buttons use dark text, never white.
